# Аудит RestartVPN 0.1: найденные ошибки и исправления

Дата: 24.11.2026. Объект: приложение RestartVPN 0.1 (C#, net48, WinForms).
Метод: статический разбор + 37 юнит-тестов + smoke-прогоны (headless, трей,
диалог настроек, установка/удаление, self-test). Живой VPN не трогали:
ни одной команды `connect` / `disconnect` / `taskkill` не отправлено.

## 1. Итог

* Найдено и исправлено: **22** дефекта (включая 5 высокой критичности).
* Остаётся известных ограничений: **12** (раздел 4).
* Тесты: **37/37**, сборка без предупреждений.
* Артефакт после исправлений: `dist/RestartVPN-0.1.0.exe`.

Критичными были:

1. устаревшая строка `AUTH_FAILED` из прошлой сессии навсегда блокировала
   перезапуски (P1);
2. провал `connect` обходил экспоненциальный backoff и повторялся каждые 30 с (P1);
3. при старте в трее события монитора могли обновлять окно из фонового потока (P1);
4. закрытие окна в трей отменяло завершение Windows (P1);
5. автозапуск, выбранный при установке, сбрасывался первым запуском (P1).

## 3. Как проверялось

~~~powershell
dotnet test tests\RestartVpn.Tests -c Release        # 37/37
dist\RestartVPN-0.1.0.exe --selftest --config YOUR-settings.json   # exit 0
~~~

* headless 18 с в `MonitorOnly`: цикл, повторы, журнал, ротация;
* трей 20 с: окно скрыто, события не роняют UI, диалога ошибки нет;
* диалог «Настройки» открыт и закрыт через Win32-сообщения, приложение живо;
* установка/удаление: `--install --silent`, `DisplayIcon` с кавычками,
  `--uninstall` при работающем приложении → exit 1, после закрытия → папка и
  реестр удалены;
* живая среда: существующий монитор и `openvpn.exe` остались работать; приложение
  не отправляло им команд.

## 4. Известные ограничения (не исправлены)

| ID | Уровень | Проблема | Рекомендация |
|---|---|---|---|
| O1 | P2 | `ApplySettings` синхронно ждёт `StopAsync` до 15 с; сохранение настроек во время VPN-действия подвешивает окно | Сделать `ApplySettingsAsync` и `async` обработчики в UI |
| O2 | P2 | Все цели падают с `TlsFailure`/`DnsFailure` при «подключённом» туннеле → VPN перезапускается; на Win7 это может быть устаревший корневой сертификат, а не блокировка | Учитывать `ProbeOutcome` в политике: для всех TLS/DNS — предупреждение, не перезапуск (опция) |
| O3 | P2 | `OpenVpnLogReader` читает хвост 256 КБ при каждом опросе статуса (раз в 5 с) | Кэш по (path, mtime, length) или хвост 32–64 КБ |
| O4 | P3 | Нет мастера быстрой настройки: при пустых настройках трей показывает только подсказку | Добавить в меню трея «Быстрая настройка» с выбором .ovpn |
| O5 | P3 | Состояние `snooze`, история перезапусков и предохранитель не переживают перезапуск приложения | Сериализовать в `state.json` |
| O6 | P3 | `SingleInstance` использует `Local\`: два RDP-сеанса могут управлять одним профилем | `Global\` или проверка владельца сеанса |
| O7 | P3 | Проверка «приложение запущено» при удалении идёт по имени образа `RestartVPN`; переименованный exe обойдёт защиту | Named event shutdown вместо перебора процессов |
| O8 | P3 | Ротация журнала использует имя с точностью до секунды; две ротации в одну секунду → `File.Move` падает (журнал продолжает расти) | Добавлять миллисекунды/GUID |
| O9 | P3 | На .NET Framework разрешение DNS может превысить `TimeoutMs`; чтение тела отменяется между чтениями, а не внутри `Read` | Отдельный DNS-таймаут, `ReadAsync` с токеном |
| O10 | P3 | 4xx (включая 403 WAF) по умолчанию считается доступностью | Документировать `ExpectedStatus`; для строгих проверок задавать `[200]` |
| O11 | P3 | `SettingsForm` показывает размер журнала минимум 1 МБ; конфиг с 64 КБ при сохранении станет 1 МБ | Отдельное поле в КБ или сохранение исходного значения |
| O12 | P3 | Версия в `Directory.Build.props` не берётся из тега, бинарник не подписан | Передавать `/p:Version` в CI, подпись кода |

## 5. Ограничения аудита

* Реальные перезапуски VPN не выполнялись — проверены политика, сопоставление
  профиля, пробы, настройки и UI-сценарии, но не живой туннель.
* Windows 7 проверена по составу API (.NET 4.8, TLS 1.2), не на железе.
* Нагрузочного теста (сотни целей, сутки работы) не было.
