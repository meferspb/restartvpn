# Архитектура RestartVPN 0.1

## 1. Задача и границы

**Цель.** Один установочный exe для Windows 7 SP1 / 10 / 11, который:

1. запускает обход блокировки — поднимает выбранный профиль OpenVPN, если он не поднят;
2. контролирует доступность заданных сайтов;
3. при отказе (по настраиваемой политике) перезапускает **только этот профиль**;
4. имеет гибкие настройки (JSON + GUI), журнал и трей;
5. полностью open source (MIT), без телеметрии и без скрытых загрузок.

**Не делает (сознательно):**

* не изменяет .ovpn, маршруты, DNS, прокси, firewall и сетевые адаптеры;
* не трогает другие профили и чужие VPN-подключения;
* не устанавливает службы, драйверы и не требует прав администратора;
* не скачивает обновления и не отправляет данные наружу;
* не управляет VPN через OpenVPN Service (в 0.1 — только OpenVPN GUI).

## 2. Почему .NET Framework 4.8 + WinForms

| Вариант | Win7 | Один exe | Итог |
|---|---|---|---|
| .NET 8/9 self-contained | нет | да | не подходит |
| Go 1.21 | да | да | GUI/трей и WMI без зависимостей — много ручной Win32-работы; поддержка Win7 на грани |
| Rust | только tier-3 win7 target | да | сложная сборка, GUI с нуля |
| Electron | нет (Win10+) | нет | объём, память |
| Python | нет | нет | нужен интерпретатор |
| **.NET Framework 4.8 + WinForms** | **да (SP1 + 4.8)** | **да** | выбран |

.NET Framework 4.8 входит в Windows 10/11; на Windows 7 SP1 ставится отдельно
(офлайн-установщик, ~110 МБ) — это документированное требование, а не скрытая зависимость.

Сборка: SDK-style проект `net48`, но исходники `RestartVpn.Core` компилируются
**внутрь** exe (см. `src/RestartVpn.App/RestartVpn.App.csproj`). Поэтому релиз —
один файл `RestartVPN.exe`, без DLL рядом. Core-проект остаётся для тестов.

    +------------------------------------------------------------------+
    | RestartVPN.exe                                                   |
    |                                                                  |
    |  Program / CliOptions / ConsoleHost   — режимы запуска           |
    |  Installer / SingleInstance           — установка, один экземпляр|
    |  TrayContext / MainForm / SettingsForm— UI (WinForms, трей)      |
    |  AppController                        — владелец настроек и лога |
    |                                                                  |

    |    OpenVpnCommandLine                 — точное сопоставление     |
    |    OpenVpnLogReader                   — признаки туннеля         |

Ключевое разделение: **DecisionEngine не делает I/O** и получает `now` параметром.
Поэтому политика проверяется юнит-тестами без VPN, сети и таймеров.

## 4. Поток данных

1. `MonitorService` раз в `probeIntervalSec` параллельно опрашивает включённые цели.
2. Неудача повторяется один раз через `retryDelayMs` с укороченным таймаутом.
3. Счётчик `consecutiveFailures` растёт/сбрасывается; в снимок попадают
   только актуальные значения и время последней неудачи.
4. `OpenVpnGuiBackend.GetStatus()` читает процессы (WMI) и хвост журнала OpenVPN.
5. `DecisionEngine.Evaluate` возвращает одно из решений (таблица ниже).
6. Действие выполняется под `SemaphoreSlim` (одновременно только одно), затем
   `WaitRecoveryAsync` ждёт восстановления затронутых целей.
7. Результат пишется в журнал и JSONL, UI получает событие и обновляет снимок.

## 5. Политика принятия решения

### Определения

* **Цель недоступна** — `consecutiveFailures >= failureThreshold`.
* **Кворум** — `All` (все включённые), `Majority`, `Any`, `Count:N`.
* **Свежесть** — цель учитывается, если её последняя неудача не старше
  `max(correlationWindowSec, 2*probeIntervalSec+10)`. Это защита от «залипших»
  счётчиков после сна/остановки процесса.
* **Признак туннеля** — процесс с точным `--config` плюс последняя запись журнала
  OpenVPN (`Initialization Sequence Completed`, `AUTH_FAILED`, `SIGTERM`,
  `Restart pause` и т. п.). Журнал читается только на чтение.

### Таблица решений

| Условие | Действие |
|---|---|
| Нет недоступных целей | ничего |
| Кворум не собран | предупреждение «проблема сервиса» |
| Режим `MonitorOnly` | только предупреждение |
| Фатальная ошибка OpenVPN (AUTH_FAILED, TUN/TAP, конфиг) | предупреждение, перезапуск не поможет |
| Профиль не запущен | `Connect` (без убийства процессов) |
| Процесс есть, журнал говорит «остановлен/переподключение» | мягкий перезапуск |
| Туннель «подключён», цели недоступны | перезапуск (по умолчанию), либо предупреждение при `requireTunnelEvidence=true` |
| Предохранитель открыт / пауза не истекла | ждать, в журнал — причина |

### Backoff и предохранитель

`gap = min(maxGap, minGap * 2^failedAttempts)`, затем:
`gap = maxGap`, если за час было `maxRestartsPerHour` попыток;
случайный разброс ±`jitterPercent`; после `failedRestartsBeforeCircuit` неудач —
`circuitCooldownSec` только оповещений. Успех сбрасывает и счётчик, и предохранитель.

## 6. Инварианты безопасности

| ID | Инвариант | Где обеспечен |
|---|---|---|
| S1 | Приложение управляет только профилем, чей `--config` совпадает по имени файла/пути | `OpenVpnCommandLine.MatchesProfile`, тесты |
| S2 | Никогда не убивать `openvpn.exe` по имени образа | `OpenVpnGuiBackend.HardRestart` (только matched PID) |
| S3 | При невозможности прочитать командные строки — не убивать ничего, только предупредить | `TryQueryProcesses` + решение `VpnAlert` |
| S4 | Не менять .ovpn, маршруты, DNS, прокси, адаптеры, firewall | в коде нет таких операций |
| S5 | Не запускать действия в режиме `MonitorOnly` | `DecisionEngine` + `_autoEnabled` |
| S6 | Один экземпляр на VPN-профиль (даже при разных файлах настроек); второй — показывает окно первого | `SingleInstance` (mutex по имени профиля + событие) |
| S7 | Ограниченное число перезапусков и предохранитель | `DecisionEngine` |
| S8 | Пауза (snooze) и «только наблюдать» доступны всегда | UI + `MonitorService` |
| S9 | Установка per-user, без администратора и служб | `Installer` |
| S10 | Никакой телеметрии и сетевых запросов, кроме целей мониторинга | `HttpProbe` |

## 7. Пробы

* `HttpClient` в процессе: без `curl.exe` и без дочерних процессов.
* `ResponseHeadersRead`: тело не скачивается, если не задан `bodyPattern`
  (тогда читаются первые `maxBodyBytes`).
* Таймаут на запрос через `CancellationTokenSource`, а не только `HttpClient.Timeout`.
* Классификация: `Ok`, `HttpStatus`, `BodyMismatch`, `Timeout`,
  `DnsFailure`, `TlsFailure`, `ConnectionFailure`.
* По умолчанию 1xx–4xx — успех (сервер ответил), 5xx — недоступность;
  `expectedStatus` на цель перекрывает это правило.
* Прокси по умолчанию не используется (как `--noproxy *` в старом скрипте), включается
  настройкой `probe.useSystemProxy`.
* TLS 1.2 включается в `ServicePointManager` (важно для Win7); ошибки TLS
  классифицируются отдельно, чтобы не путать с блокировкой.

## 8. VPN-слой

`OpenVpnGuiBackend`:

* находит .ovpn так же, как GUI: `%USERPROFILE%\OpenVPN\config`,
  `...\config\<name>\<name>.ovpn`, `%ProgramFiles%\OpenVPN\config`;
* команды — `openvpn-gui.exe --command connect|disconnect <name>`;
  если GUI не запущен, стартует его с `--connect <name>`;
* в AutoRestart профиль поднимается при старте (`vpn.connectOnStart`), если он не запущен;
* «жёсткий» перезапуск — только PID, у которых `--config` указывает на наш файл;
* таймаут команды не убивает GUI (в отличие от старого скрипта);
* статус — процесс + хвост журнала; «процесс жив» не считается доказательством туннеля.

Ограничения 0.1: OpenVPN, запущенный как служба (`openvpnserv`), не управляется;
если WMI недоступен, приложение не будет убивать процессы (безопасное поведение).

## 9. Настройки

* Файл: `%APPDATA%\RestartVPN\settings.json` (portable: `<exe>\data\settings.json`).
* `--config <path>` — альтернативный файл; данные/состояние — рядом с ним.
* Приоритет: значения по умолчанию → JSON → валидация; неизвестные поля игнорируются
  (совместимость вперёд), ошибки показываются с путём (`targets[0].url`).
* Сохранение атомарное (tmp + `File.Replace`, бэкап `.bak`), UTF-8 с BOM
  (чтобы Win7 Notepad открывал корректно).
* Полный справочник — `docs/SETTINGS.md`. Готовый settings.json в репозиторий
  не входит: файл создаётся приложением при первом запуске.

## 10. UI и установка

* Приложение живёт **в трее** и не показывает главное окно при запуске.
* Меню трея: «Показать окно», «Включить/Выключить мониторинг», «Проверить
  сейчас», «Перезапустить VPN», «Пауза 30 минут», «Возобновить», «Настройки»,
  «Выход». Левый и правый клик по значку открывают это меню.
* Состояние мониторинга запоминается в `Ui.MonitoringEnabled`: выключенное
  приложение при следующем старте не запускает цикл, пока пользователь не
  включит его снова.
* Настройки — отдельное диалоговое окно из трея; автоматического окна первого
  запуска нет (при пустых настройках показывается подсказка в трее).
* Закрытие окна = свернуть в трей (настраивается); выход — только через меню/кнопку.
* Установка: копия exe в `%LOCALAPPDATA%\Programs\RestartVPN`, ярлык в меню
  «Пуск», запись `HKCU\...\Uninstall\RestartVPN`, опционально автозапуск
  (`HKCU\...\Run`) и ярлык на рабочем столе. Удаление — `--uninstall`.
* Portable: `--portable` или наличие `data\settings.json` рядом с exe.

## 11. Журналирование

* `restartvpn-<profile>.log` — текст, локальное время со смещением, ротация по
  размеру **во время работы**, хранится `keepFiles` файлов; без профиля —
  `restartvpn.log`.
* `restartvpn-<profile>.events.jsonl` — машиночитаемые события (UTC, код, цель).
  Отдельные файлы на профиль нужны, потому что два профиля могут работать
  одновременно и не должны перемешивать журнал.
* Уровни Error/Warn/Info/Debug; повторяющиеся отказы после порога пишутся на Debug,
  чтобы не раздувать журнал.
* Ошибки записи не роняют мониторинг; последняя ошибка доступна в UI.

## 12. Безопасность

| Угроза | Мера |
|---|---|
| Случайно убить чужой VPN | точное сопоставление, запрет kill по имени, отказ при неизвестных процессах |
| Вредоносный `settings.json` | строгая валидация URL/схемы; никаких shell/команд из конфига |
| Локальный пользователь подменяет exe | установка per-user, рекомендация подписи кода (roadmap), нет автозагрузки из temp |
| Утечка данных | нет телеметрии; журнал только локальный |
| Повышение привилегий | `asInvoker`, без служб/драйверов |

## 13. Сборка и CI

* `dotnet build src/RestartVpn.App -c Release` → один `RestartVPN.exe`.
* `dotnet test tests/RestartVpn.Tests` — 37 тестов (политика, сопоставление
  профиля, настройки, пробы, ротация журнала).
* `scripts/build.ps1` кладёт exe и SHA-256 в `dist/`.
* GitHub Actions: restore → build → test → artifact (см. `.github/workflows/ci.yml`).

## 14. Тестирование

| Уровень | Что покрыто |
|---|---|
| Юнит-тесты | контрпример C1, кворумы, backoff, предохранитель, connect без процесса, фатальные ошибки, «похожий профиль не совпадает», валидация, JSON, probe на локальном TCP-сервере |
| Self-test (`--selftest`) | read-only: настройки, профиль, GUI, состояние VPN, пробы |
| Smoke | headless-цикл, старт трея, install/uninstall, отсутствие действий в MonitorOnly |
| Не покрыто | реальные перезапуски на Win7/10/11, служба OpenVPN, DPI-сценарии, подпись |

## 15. Roadmap

1. **0.2** — служба OpenVPN, WireGuard-бэкенд, локализация (ru/en), расписание
   «не трогать в рабочие часы», проверка TLS-сертификата цели.
2. **0.3** — подпись кода, автообновление из GitHub Releases (opt-in), метрики
   uptime, экспорт отчёта.
3. **1.0** — стабильный формат настроек, миграции, установщик Inno Setup (опционально),
   матрица тестов на Win7/10/11.

Известные ограничения 0.1: только OpenVPN GUI; UI на русском; нет подписи;
нет автоподъёма службы; WMI обязателен для точного сопоставления.
